Wired tiger storage Engine
Cache + Checkpoint+ Journal

read operation --> query engine --> execution plan --> based on winning plan ->check if the data is present in cache
	-- cache hit -- return the data to user
  -- cache miss -- fetch the data from the disk -> store the data in the cache (if needed eviction)--> send data to the user
  
Write operation -- write gets executed + persisted
write operation --> query engine --> store the data in the cache --> every 60 secs --> flush the data to the disk--> persisted
cache --> checkpoints --> dirty page(modified pages)--> flush the dirty pages to disk
every 60 sec , a checkpoint is created and flushed to the disk
Journal -- write ahead log -- first write op is written to journal, then the write operation goes to the cache 
Journal is also pushed to the disk;

checkpoint created at 10:25:00
Write Operation: 10:25:05
Cache -- dirty page;
10:25:35 abrupt server shutdown -- problem: cache will get cleared; dirty pages -- lost; 
last 35 seconds writes will get lost because the cache got cleared

Lose 60 seconds -- write intensive app -- NO

Journal -- before write can happen, the operation is added to the journal

10:25:35 -- abrupt shutdown
Checkpoint : 10:25:00 (last checkpoint before the shutdown )
Play the journal entries from 10:25:00 to 10:25:35
-- All the data is restored

Journal -- Persisted -- every 100ms/ size of journal file reaches 100 mb of data

Loss of data -- max of 100ms -- writes may be lost

Journal and checkpoints are features of wired tiger storage engine.
Each server(standalone, member of replica set ) which uses wr storage engine -- will have these features
